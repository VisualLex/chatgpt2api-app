# 历史任务

状态：已实现。本机管理页面的图片/GIF、账号授权、额度刷新使用持久后台任务；托管后端另外采集第三方 API 请求记录。下文记录交互与实现约定。

## 入口和首期范围

顶部增加「历史任务」，与「图片生成」「号池管理」并列。页面展示所有已记录任务，进行中的任务也能查看。

当前覆盖图片和 GIF、邮箱/TXT 导入后的账号授权、待授权账号处理以及单个/全部账号额度刷新。托管 Python 后端同时采集第三方客户端的 `POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/images/generations` 和 `POST /v1/images/edits` 请求，列表可通过「API 请求」类型筛选。管理页面调用同一后端时不会再生成重复的 API 记录。历史版本的任务、更新前的 API 请求、高级导入来源以及外部自行部署的后端暂不采集，也不会通过扫描图片目录虚构旧任务记录。

## 列表和详情

列表默认按创建时间倒序，支持任务类型、状态、日期范围筛选和分页。

| 内容 | 展示方式 |
| --- | --- |
| 任务 | 图片缩略图或类型图标、简短摘要、任务编号 |
| 状态 | 排队中、进行中、成功、部分成功、失败、已中断/结果未知 |
| 时间 | 创建时间、耗时；进行中任务显示已等待时长 |
| 结果 | 图片数量，或批处理的成功/失败/跳过数量 |
| 操作 | 查看详情；按类型提供下载、沿用参数或重试失败项 |

点「详情」打开弹窗：

- 图片/GIF：完整提示词、模型、分辨率、参考图、动画参数、结果预览和下载。「沿用参数」回填生成页，由用户再次提交。
- 导入/授权：总数、成功/失败/跳过数量、处理结果和失败原因。「重试失败项」创建新任务，关联原任务，仅处理失败项。
- 额度刷新：总数、已处理数、查询异常数和进度。「查看号池」跳转账号管理。
- API 请求：接口、模型、流式标记、请求文本摘要、HTTP 状态、耗时和上游返回的 Token 用量。已采集的图片结果支持预览和下载，不提供沿用参数或直接重试。旧版未关联图片的记录显示未保存结果，不会仅凭文件时间猜测关联。第三方客户端断开时，记录可能显示「已中断 / 结果未知」。

没有上游真实进度的图片任务仅显示「进行中」和耗时，不伪造百分比。图片已被手动移除时，保留任务记录并显示「结果文件不存在」。

## 执行和持久化

改造前，图片生成和账号授权使用同步长请求，浏览器内存只保留最近一次结果；额度刷新提供 `progress_id` 轮询。本机图片目录只能保存产物。现在由任务服务持久保存参数、状态和结果，原同步接口保留兼容。

本机任务服务先原子写入任务记录并返回 ID，再进入后台队列执行；页面查询状态。浏览器刷新、切页或关闭后可重新查看任务。任务元数据保存在本机数据目录的 `task-history.json`，参考图和结果文件保存在 `task-files/`；不增加额外数据库或服务。默认串行处理并保留最近 1000 条记录，清理时只移除已结束记录。

API 请求保持原有同步或流式执行方式，由 Python 入口旁路记录到本机数据目录的 `api-request-history/`，每条请求独立原子写入文件，与页面任务合并排序、筛选和分页。该目录独立保留最近 1000 条请求，清理时保留进行中的记录。Node 与 Python 不会共同覆盖 `task-history.json`。记录失败不阻断原 API 请求，流式内容随收到的块继续转发。后端重启后将未结束请求标记为「已中断 / 结果未知」，不会重放请求。

更新入口后需重启托管的 Python 后端；刷新管理页面或接管旧后端进程不会让运行中的旧入口加载采集逻辑。

- 提交时带请求 ID，避免双击或网络重发创建重复任务。
- 程序重启后，未结束任务保守标记「已中断/结果未知」，不自动重放。额度刷新保留上游进度编号，当前版本也不自动恢复轮询，避免错误地重新提交查询；用户可核对号池后手动重试。
- 重试产生新的任务 ID 并保留原记录，不覆盖失败历史。
- 任务记录保存业务参数、进度、结果和经过清理的错误；账号任务只关联本机记录 ID，不复制 Token、密码、2FA 或完整原始响应。
- API 请求仅保存白名单元数据、有限请求文本摘要、HTTP 状态、响应字节数和数值用量，不保存 Authorization、Cookie、API Key、完整对话、原始响应和图片 Base64。失败提示不复制可能含凭据的上游异常原文。
- 图片结果解码为独立 PNG/JPEG/WebP/GIF 文件保存在 `task-files/`，记录只引用文件编号、格式和大小；沿用受登录保护的文件读取接口。删除请求记录会保留已保存的图片文件。
- 每条 API 请求最多保存 8 张、每张不超过 32MB；图片响应及单个图片流式事件的分析上限为 72MB。URL 结果只读取固定本机图片目录中的安全文件，不下载外部地址。保存失败保留原 API 状态，并在详情提示图片未保存的原因。
- 采集采用有界分析，超大请求或响应仍正常转发，但可能只记录接口和状态，缺少模型、文本摘要或用量。
- 「删除历史记录」默认仅移除记录；清理图片作为单独明确的操作。

每条记录包含 `id`、`type`、`status`、`summary`、`createdAt`、`startedAt`、`finishedAt`、`params`、`progress`、`result`、`error`、`parentTaskId`。账号敏感凭据仍留在现有加密凭据存储中。输入图片与结果按文件 ID 读取，缺失时保留记录并提示文件不存在；参考图不完整时需要重新选择，不能直接重试为纯文本生图。

## 管理接口

沿用当前已登录的本机管理接口，增加：

- `POST /local/tasks`：提交任务，立即返回任务 ID。
- `GET /local/tasks`：合并页面任务与 API 请求，按类型、状态、时间和页码查询。
- `GET /local/tasks/:id`：详情与最新状态。
- `POST /local/tasks/:id/retry`：为页面任务创建关联的重试任务；API 请求记录不能重试。
- `DELETE /local/tasks/:id`：清理已结束任务的历史记录。
- `GET /local/task-files/:id`：登录后读取已登记文件的 MIME 和 Base64，由页面预览和下载，不接受任意本机路径。

以上为受登录保护的管理桥接路径，使用现有 `/api/chatgpt2api-native/manage` 同源 POST 传递 `{path,method,body}`，不向第三方 `/v1` 接口暴露。日期筛选界面按本地全天转换为 ISO 时间范围。

验收重点：刷新页面后恢复查看、关闭网页后页面任务继续、程序重启不重复生图、失败原因可查、批处理可区分部分成功、结果文件缺失时页面可正常使用；API 成功、失败、流式及断连状态可查，页面调用不重复记录，凭据和原始响应不进入请求记录。
